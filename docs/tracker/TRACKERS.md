# Tracker

Work tracking for the AI agent. Everything here is short-horizon and
actionable; it is not documentation and not a roadmap. Documentation lives in
the parent [`docs/`](../).

- [issues/](./issues/) - reviewed issues from critiques and audits, with a board
  index in [`issues/ISSUES_TRACKER.md`](./issues/ISSUES_TRACKER.md).
- [specs/](./specs/) - feature specs, from `/to-spec`.
- [tasks/](./tasks/) - actionable tickets with blocking edges, from `/to-tickets`.

The engineering skills read their configuration from the tracker convention in
[`issues/ISSUES_TRACKER.md`](./issues/ISSUES_TRACKER.md) and the labels in
[`../TRIAGE_LABEL.md`](../TRIAGE_LABEL.md).
